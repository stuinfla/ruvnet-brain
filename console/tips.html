RuvNet Brain · the guide

You're using it as a vector database. That's the smallest thing it does.

Vectors in, neighbours out — that part is easy to find, so nearly everyone stops there. What came with it is a harness around the model you already pay for: hooks that learn from your edits, memory that returns on its own, gates that can refuse a bad write, routing that quietly picks a cheaper model. Most of it ships switched off, or simply never asked for. Here's the rest of what you own.

“I don't have to load 350 skills in Ruflo that 99% of which I never use. I can specifically learn and say that, for this particular task, I need a particular plugin or skill. And the system is smart enough to be able to say, okay, I've seen this before, therefore, I know that I need this particular skill to do this particular task.”

— rUv · hackerspace call, 2026-07-16 · sourced from the brain (ruv-meetings)

the other 90%

Ten things you already own — and probably aren't using

None of these is a new purchase; they arrived with what you installed. Each one says what it is in one line, what it actually buys you, and how you'd know whether it's on. The colour tells you the cost of switching it on: cyan has no switch to flip, amber is one sentence away, green is one command away. Whether any of them is on right now is a question only the console can answer.

10
  • 01 · Self-learning hooks

    Hooks that sit on your edits and commands and record what actually worked.

    buys you

    Suggestions and routing shaped by your repo instead of generic defaults — it stops re-deriving how your project works every session.

    how to tell

    Run ruflo hooks list. Every row carries an Enabled and a Last Executed column — all “No” and “Never” means nothing is learning yet.

  • 02 · Pretraining on your own repo

    A one-shot pass that reads a repository and bootstraps patterns out of it.

    buys you

    Day-one routing that already knows your layout and conventions, instead of a cold start it spends weeks recovering from.

    how to tell

    ruflo hooks pretrain runs it; ruflo hooks metrics shows what it took away. The counters live at ~/.claude-flow/neural/stats.json — no file, no pretraining.

  • 03 · Memory that comes back on its own

    A per-project store of decisions, written as you work and surfaced when you return.

    buys you

    You stop re-explaining the project. Last week's decision is already in the room before you ask for it.

    how to tell

    Run ruflo memory search "<something you decided>" in the project. Rows back means it's recording; the store is .swarm/memory.db inside that project, not a global one.

  • 04 · Routing to a cheaper model

    A router that sends each task to the least expensive model that can actually do it.

    buys you

    The expensive model sits idle on work that never needed it — and every route leaves a receipt, so the saving is counted rather than claimed.

    how to tell
    “do this cheaper”

    Receipts append to ~/.cache/ruvnet-brain/token-ledger.jsonl; the console's savings card totals them. No file means nothing has been routed yet.

  • 05 · Gates that can refuse a write

    Checks that read a change before it lands, and can stop it outright.

    buys you

    The bad edit never happens. You are not reviewing damage after the fact, which is the only kind of review that costs a whole afternoon.

    how to tell

    Refusals are logged to ~/.cache/ruvnet-brain/gate-blocks.jsonl; the console's gates card counts them. An empty log means nothing has been refused — not that nothing is armed.

  • 06 · Your corrections, kept as rules

    The things you've told it — “always do X”, “never do Y” — captured in one file.

    buys you

    A correction you gave once stops being a correction you give weekly.

    how to tell

    Open ~/.config/ruvnet-brain/lessons.json. Each entry carries a status — one still marked candidate is recorded but not yet in force, which is the difference people miss.

  • 07 · Jobs that run while you sleep

    Scheduled background work that refreshes the knowledge, the model list and the routing.

    buys you

    The stack is current when you sit down, without you remembering to update anything.

    how to tell

    On macOS, launchctl list | grep ruvnet. The second column is each job's last exit code. Nothing listed means none are installed — which is a normal, healthy state, not a fault.

  • 08 · A harness policy actually in force

    MetaHarness freezes the model and improves what wraps it; the winner gets written down.

    buys you

    The wrapper keeps getting better on the model you already pay for — no retraining, no second subscription. (The word is explained further down.)

    how to tell
    “score my harness”

    ~/.claude-flow/harness-active-policy.json holds the policy currently applied, or does not exist at all. Say the phrase above to see where yours stands.

  • 09 · Tool servers it can already call

    MCP servers registered once, globally, so every session can reach them.

    buys you

    Searching rUv's real source, driving a browser, hitting the vector cache — from inside the conversation, with no copy-paste.

    how to tell

    ~/.claude.json lists them under mcpServers. Careful: that proves they are configured. Nothing on disk proves a server is reachable, so nobody — including this page — should tell you they're connected.

  • 10 · Skills already loaded in every project

    Named commands installed at user scope, so they follow you into every repo.

    buys you

    A whole disciplined workflow behind one word instead of a paragraph of instructions you retype.

    how to tell

    Type / in Claude Code to see what's live; ~/.claude/settings.json lists them under enabledPlugins. The board of five is at depth 3 below.

It's the drawer of attachments that came with the appliance. Nothing here is an upsell — the only thing missing was knowing they were in the box.

why wrapping the model is the whole lever

Same model. Same prompt. Everything around it.

rUv's lever isn't a smarter model — it's what wraps the one you already have. Plain Claude Code sends your prompt straight at an expensive model and takes whatever comes back. The harness grounds it, routes it to the cheapest model that can actually do the job, hands back what your project already decided, inspects the write before it lands, and checks it on the way out. You type the same thing either way.

Finding things

HNSW index
Approximate nearest-neighbour search — the default when the corpus is big. ruvector-core/src/index/hnsw.rs
Flat index
Exact search, no approximation, for when the corpus is small enough. ruvector-core/src/index/flat.rs
Hyperbolic HNSW
Poincaré-ball geometry for tree-shaped data — parent/child distances survive the embedding. For taxonomies and code trees. ruvector-hyperbolic-hnsw/src/hnsw.rs
RaBitQ quantisation
32× memory reduction with a Hamming prefilter — reach for it when a large corpus stops fitting comfortably. ruflo · embeddings_rabitq_build
Product quantisation
Compressed vectors, smaller index. ruvector-core/src/advanced_features/product_quantization.rs
Matryoshka embeddings
Progressive retrieval: a cheap coarse pass first, full precision only for finalists. advanced_features/matryoshka.rs
Hybrid search
Combines several vector representations in one query. advanced_features/hybrid_search.rs
Multi-vector search
Joint embeddings — one item represented by several vectors. advanced_features/multi_vector.rs
Filtered search
Vector search with metadata predicates applied. advanced_features/filtered_search.rs
Sparse vectors
Efficiency gains where the representation is mostly zeros. advanced_features/sparse_vector.rs
Graph RAG
Retrieval-augmented generation over a graph rather than a flat list. advanced_features/graph_rag.rs

Getting better over time

SONA
Self-Optimising Neural Architecture — trajectory tracking, pattern recognition, and memory protection so new learning does not erase old. ruvllm/src/sona.ts
Micro-LoRA
A deliberately tiny adapter (rank 1–2) driving SONA's instant loop — adaptation without retraining anything large. ruvllm/src/sona.ts
MicroLoRA SDK
Browser-based LoRA fine-tuning of small models, built for edge deployment and a minimal memory footprint. edge-net/pkg/models/microlora.js
EWC++
Continual learning that avoids catastrophic forgetting — the reason adaptation does not cost you yesterday's behaviour. @ruvector/sona

Remembering things

Agent memory
Thousands of memory clusters with coherence-weighted compaction — old memory is condensed, not truncated. ruvector-agent-memory
Hopfield associative memory
Recall a whole pattern from a partial cue. ruvector-nervous-system · hopfield::ModernHopfield
Dentate-gyrus separation
Keeps similar memories from blurring into each other. ruvector-nervous-system · separate::DentateGyrus
BTSP
One-shot learning — a single exposure is enough to lay something down. ruvector-nervous-system · plasticity::btsp

Everything else in the drawer

Sparse inference embeddings
PowerInfer-style sparse feed-forward nets with a configurable sparsity ratio. ruvector-sparse-inference
CNN backbone
MobileNetV3 (small and large) for image features. ruvector-cnn/src/backbone/mod.rs
Attention CLI
compute · benchmark · convert · serve · repl, driven by a YAML config. ruvector-attention-cli

setup · the question people keep asking

Plugin, global, or both? You want both — and they aren't rivals.

RuvNet Brain is two layers, not two competing install methods. One command sets up both, and you run it once.

◎

The surface — the Claude Code plugin. The search_ruvnet tool, the grounding hooks, and the /configure console. Installed once at user scope, so it works in every project. This is what makes Claude actually use the stack instead of drifting back to the classical defaults it was trained on.

The knowledge — the brain bundle. rUv's real source, indexed, at ~/.cache/ruvnet-brain/kb. Downloaded once from the latest Release; the search_ruvnet tool reads it locally — no cloud, no API key. Refreshed when a new Release ships, never re-fetched per query.

One command wires both. npx ruvnet-brain installs the plugin and downloads the bundle, narrating each step — that's the whole setup. Prefer to do it by hand? claude plugin marketplace add stuinfla/ruvnet-brain, then claude plugin install ruvnet-brain@ruvnet-brain --scope user.

Running both layers is not wasted resources — they do different jobs: the npm package installs and updates; the plugin is the runtime surface Claude loads each session.

Bare npx …@latest --update is for a one-off update, not a persistent install — the always-on grounding lives in the plugin's hooks, which a throwaway npx copy never wires. Keep the plugin installed at user scope; reach for npx only to install or update.

Which am I actually running? The console shows your real stack — every rUv piece it finds and whether each one is current. Want something it didn't find, like ruflo or agentic-flow? You have three ways to add it, and none is forced on you: the plugin marketplace, npm i -g <tool>, or npx <tool> for a one-off. The Brain works with any of them.
