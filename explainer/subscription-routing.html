2 The Two-Lens Rule: Personal Coding vs. Deployed Apps

One of the biggest mistakes teams make is using a pay-by-the-drink cloud proxy for personal coding—or hardcoding literal model names inside production apps.

Lens 1 · $0 Marginal Cost

Personal Coding on Your Machine

You already prepaid for flat-rate seats (Antigravity Ultra, Claude Max, ChatGPT Plus, SuperGrok). Use a local subscription-only router that strips all API keys and keeps paid cloud proxies OFF.

Stay in-vendor 90% of the time: 93%–97% of input tokens are warm prompt cache reads. Bouncing routine turns across vendors triggers a cold cache (5x–10x token penalty + 20s lag).

Lens 2 · Zero Hardcoded Models

Deployed Production Apps (SaaS / Cloud)

Personal subscriptions cannot run production user traffic. Here is where a dynamic proxy/gateway (like Meta Proxy, OpenRouter, or externalized APP_MODEL_TIERS_JSON) shines.

Never hardcode a model ID in app code. Request capability tiers (fast, medium, hard, exceptional) so apps automatically upgrade as models improve with zero code deploys.

5 The 4 Mandatory Quota-Hygiene Rules + Weekly Auto-Refresh

Rule 1

Subagent Isolation

Offload any >5 file search or log grep to a fast subagent returning a 20-line summary so raw files never bloat main chat context.

Rule 2

50% /compact Guard

Flash ⚡/compact in your statusline at 50% context. Compacting at 50% cuts per-turn token burn by 5x–10x immediately.

Rule 3

Pre-Distilled Frontier

Never let Fable 5.2 or xhigh roam a repo (KingBench 4: 212M vs 27M tokens). Gather exact files in the coordinator first.

Rule 4

Nightly + Weekly Sync

Auto-refresh CLI model caches weekly/nightly, run a 13-point self-audit watchdog, and compare 7-day vs. 60-day distribution metrics.
