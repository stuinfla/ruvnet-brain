## Per-case findings

stable-spine-recovery:3 scenarios actually run update-apply, inspect active.json and installed runtime bytes. Synthetic version strings are fixture values, not current release pins. Collision message regex is secondary to failure and unchanged active state. No automatic hook requirement; payload hooks already empty. Missing child timeout is a harness robustness gap, not relevance failure.

issue-64-host-convergence: cases1-4 validate authoritative registry payload, local-vs-user ownership, cache escape rejection, corrupt managed records; cases5-6 execute exact-version selection and missing-version refusal. Case7 reads session-start-core source and requires `/hooks` trust/restart prose: obsolete as mandatory release behavior once automatic lifecycle hooks retire. Case8 requires SessionStart seed/heartbeat variable spelling and conditional: likewise obsolete in release scope; retain only explicit legacy-handler diagnostics if desired. Case9 requires installer call syntax, literal CLI arrays, convergence filename and host-update flag; actual convergence tests should own that behavior. Source refactoring preserving behavior would fail it. Windows child environments set HOME but not USERPROFILE (host-owned os.homedir may therefore disagree); use full isolated host environment when retaining cross-OS cases.

packed-clean-install: exact manifest version equality derives packed version; good. Required-file list includes historical docs/RELEASE-NOTES-4.0.md, so removing an obsolete release note would fail despite intact product runtime. Forbid repository-private paths remains useful, but startsWith('.env') is a broad package policy, not full secret scanning. Marketplace parsing requires exactly description/hooks keys, which can reject compatible schema metadata. Real wireCodexHost and persisted console import are strong artifact boundary tests. Hook silence test loops handlers without asserting any: zero registrations means zero assertions, so rename/replace with explicit hooks={} on both packed hosts. File sets and console import are not full clean install/retrieval proof. Local fallback npm pack differs from sealed CI artifact; require RUVNET_SEALED_PACKAGE at authoritative entrypoint. RUVNET_BRAIN_IMPORT_ONLY is set without restoring earlier value, a test-isolation defect if combined with other files in a shared module process.

release-publish-contract:8 cases are source string/position checks for signed identity chain, remote draft order, non-latest staging, required asset set, build/sign once, conflict refusal, compensation authorization, public-proof ordering. None invoke transaction/provider/workflow. `indexOf` ordering can be fooled by dead code/comments and fail a behavior-preserving helper extraction. Exact workflow step title `Sign this run's exact payload once` and exact needs-list spelling are unnecessary release constraints. Underlying behaviors remain important, already covered better by transaction faults and real protected artifact receipts. Recommend diagnostic-only classification, not erasing meaningful remote boundaries.

release-transaction-faults:1 converged/no-host-verification case;25 pre-boundary interruption cases;5 post-side-effect recovery cases; polling; timeout/idempotence; compensation; immutable bytes; competing/duplicate anchors; foreign npm default; receipt drift;2 finalize-intent drift cases; same-sequence race =41. Assertions bind state, provider side effects and failure; essential release safety. Boundaries list manually names implementation operations, so a new provider boundary is not automatically covered; this is a known coverage limit. Poll observations>8 reflects fake delay3+3 and polling implementation: can reject a legitimate polling optimization despite correct final state. Single stageNpm count encodes publish-once safety, not gratuitous count. Error phrase checks may need maintenance, but do not substitute for state/side-effect assertions. This is fake-provider contract proof, not live-registry execution.

console-control-completeness:5 cases merely find strings for config consumer calls, canonical user-setting names, choice paths, unavailable prose, Fix-all consent/revalidation/undo. Case1 requires literal CONFIG_CONTROL_SUPPORT=Object.freeze({}), so actually adding a supported config control can fail the test even with working consumer. Case2 hand-maintains6 setting names and calls them every canonical setting; cannot prove exhaustive coverage. Case3 title says four working paths but source search cannot prove any path executes. Cases4-5 freeze UI wording and fetch-call formatting; they do not render or click controls. Replace authority with current runtime and rendered browser acceptance; preserve these as diagnostic hints only if desired.
