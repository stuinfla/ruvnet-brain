# Handoff: release 4.7.24 (2026-10-30)

Written for the owner's local Claude Code, so it can pick this release up in the MacBook working copy and
record it in Ruflo's AgentDB memory. Everything below is what the change does and what was run; nothing in it
is a claim about machines it was not run on.

## What changed, per item

### #335 follow-up: a stuck update had no supported way out

Why: the reporter's transaction ended at `RECOVERY_REQUIRED` (live tree re-stamped after `LOCKED` sealed it, a
half-built `kb.next-<id>` left beside it). `recoverIncompleteStorageTransactions()` correctly refuses that on
every update, and `--clean --archive` never enters that path, so every later update stopped at the same refusal.

What: `kb/update-storage-transaction.mjs` adds `previewRecoveryRequired()` (read-only: every tree, its identity
and whether it matches the sealed prior or candidate) and `disposeRecoveryRequired()` (refuses unless the live
tree's sha256 equals the one the operator names; moves the candidate, rollback and failed trees intact to
`.<kb>.recovered/<id>/`, checking identity after each move; appends a terminal `DISPOSED` receipt). `DISPOSED`
is terminal in `brain-footprint.mjs` and `lifecycle-evidence-retention.mjs`; `.kb.recovered` is kept, never
swept. `bin/install.mjs` exposes it:

```bash
npx ruvnet-brain --recover-update                                      # preview, changes nothing
npx ruvnet-brain --recover-update --keep-live <sha256> --transaction <id>   # the exact line the preview prints
```

Automatic recovery is unchanged: it still refuses, and its message now names the preview.

### #377 residual: learning acknowledged before it was stored

Why: on the detached hook path the parent called `markCaptured()` before the child ran `ruflo memory store`. A
child whose store or exact readback failed left the observation marked captured for ten minutes, and every
identical observation in that window was dropped as a duplicate of a write that never happened.

What: `plugin/scripts/learn-capture.mjs`. The parent now writes only an in-flight mark (`<key>.pending`, never an
acknowledgement, expires with the child's slot). The child calls `markCaptured()` only after
`recordLearningObservation()` completes its exact readback, and clears the in-flight mark either way.

### The five unit checks red on main (d8aab9f1, CI unit-suite and canonical-qa)

- `full-suite-gate`: the autofix simulation's fixture repository has its own two test files; they are now

## Loading this into the MacBook working copy and Ruflo's AgentDB

`git pull` only touches tracked files. `.swarm/` (the AgentDB store), `agentdb.rvf` and the other ignored files
are not tracked, so a pull leaves them exactly as they are. From the working copy:

```bash
git status --short                      # commit or stash local edits first; never reset
git fetch origin && git merge --ff-only origin/main
npm ci
```

Then record it the way the product records a material event (CONTRIBUTING.md: `continuity-events`, confirmed
by exact readback). In Claude Code in that working copy, run `/ruvnet-brain:rnb-brief` and give it this file.
The same thing by hand, against the working copy's own store:

```bash
ruflo memory store --namespace continuity-events --key release-4.7.24 \
  --value "$(cat docs/handoff/2026-10-30-release-4.7.24.md)" --path .swarm/memory.db
ruflo memory retrieve --namespace continuity-events --key release-4.7.24 --value-only \
  --path .swarm/memory.db | head -3      # exact readback: the first lines of this note
```

If `git merge --ff-only` refuses, the local branch has commits main does not; stop and look before merging.
